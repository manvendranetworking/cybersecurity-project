1. Project Overview

CyberShield is a cybersecurity dashboard built using Python and Streamlit. It simulates the kind of monitoring tool that a Security Operations Center (SOC) analyst might use to watch over login activity in a company's network. The goal of the project is to demonstrate how even simple programming concepts — loops, dictionaries, and if statements — can be used to detect suspicious behaviour in security data.

All data shown in the application is entirely fictional and created for learning purposes only. The application is not connected to any real network, database, or live system.

2. Problem Statement

One of the most common types of cyberattack is a brute-force attack, where an attacker repeatedly tries different passwords to break into an account. Without a monitoring tool, these repeated failed login attempts can go unnoticed for a long time.

This project addresses that problem by building a dashboard that automatically scans login records, applies a simple detection rule, and raises an alert when suspicious activity is found — all without using machine learning or connecting to real systems.

3. Objectives

  1. Build a working security dashboard using Python and Streamlit.
  2. Load and display simulated login records in a readable table.
  3. Detect suspicious IP addresses using a simple rule-based approach.
  4. Visualise login data with clear, interactive charts.
  5. Allow users to filter records and alerts to focus on what matters.
  6. Make the code beginner-friendly, well-commented, and easy to maintain.

5. Key Features

A. Executive Overview

The dashboard opens with two rows of metric cards. The first row shows illustrative aggregate numbers (total logins, successful logins, failed logins, suspicious activities) for a larger fictional dataset. The second row shows statistics calculated directly from the 10 sample records so learners can see exactly where each number comes from.

B. Login Activity Table

Displays all 10 simulated login records in a formatted table. Users can filter by:

Login Result Username IP Address Free-text Search

Rows from flagged IP addresses are marked with a ⚠ Suspicious label in amber. The table includes a row count summary and a Download as CSV button so users can export the filtered results.

C. Visual Analytics

Three Plotly charts help users understand the data visually:

ChartWhat it shows
Login Outcome Comparison A grouped bar chart comparing the number of successful vs failed logins. A tall red bar is a warning sign.
Failed Logins by IP A bar chart showing how many failures each IP produced. Suspicious IPs turn amber, and a dashed line marks the detection threshold.
Logins Over Time A scatter plot showing each login attempt on a timeline. The rapid cluster of red dots makes the brute-force burst visible immediately.

D. Rule-Based Detection Engine

The detection logic is written using plain Python — no machine learning or external libraries. It works in three steps:

  1. Loop through every login record and count how many failures each IP address has produced.
  2. Compare each IP's failure count against the configurable threshold (default: 5).
  3. Any IP that meets or exceeds the threshold is added to the suspicious list and triggers an alert.
Example: IP address 192.168.1.77 appears in the sample records with 5 failed attempts against the admin account within approximately two minutes. The rule flags it as Medium Risk and raises a Security Alert.

E. Security Alerts

Each flagged IP generates an alert card showing the IP address, target username, number of failed attempts, risk level badge, timestamp of the first and last attempt, the reason for the flag, and four suggested investigation steps. Alerts can be filtered by risk level (High / Medium / Low). An expandable section shows the full record set for that IP.

Risk levels are assigned as follows: High ≥ 10 failures Medium ≥ 5 failures Low < 5 failures

F. Configurable Threshold

The detection threshold is adjustable from the sidebar using a number input. Changing it immediately re-runs the detection engine and updates the metric cards, charts, and alert section — no page reload needed.

7. Sample Data Description

The application uses 10 completely fictional login records set on a simulated date of 10 June 2024. The records include a mix of successful and failed logins from different usernames and IP addresses. IP address 192.168.1.77 was deliberately given 5 consecutive failed login attempts against the admin account to demonstrate how a brute-force pattern looks in real data — and to show that the detection rule catches it correctly.

A separate set of larger aggregate numbers (1,284 total logins, 973 successful, 248 failed, 63 suspicious) represents a fictional historical dataset and is clearly labelled as illustrative on the dashboard. These numbers are not calculated from the 10 sample records.

8. Limitations & Important Notes

This project is for educational purposes only. It is not a real security product.

The following limitations apply:

  1. No real data. All login records are fictional. The application does not connect to any system, database, or network.
  2. Simple detection rule. The rule only counts total failures per IP. Real systems also consider time windows, geographical anomalies, and account context.
  3. No time-window logic. Five failures spread over a week would be treated the same as five failures in one minute.
  4. Not proof of attack. A flagged IP could also be a user who forgot their password, a misconfigured application, or a test script. Human investigation is always needed.

9. How to Run the Application

  1. Install the required libraries: pip install streamlit pandas plotly
  2. Navigate to the project folder: cd project
  3. Start the application: streamlit run app.py
  4. Open the browser at http://localhost:8501
  5. Use the sidebar to navigate between sections.

10. What Was Learned

Building CyberShield covered several practical skills: using Python dictionaries and loops to process data, applying conditional logic to classify risk, building an interactive web application without knowing HTML or JavaScript, working with Pandas DataFrames to filter and display tabular data, and creating charts with Plotly that respond to user interaction.

The project also introduced the concept of separating raw data from display logic, which is a foundational principle in real-world software development. Writing helper functions for repeated tasks — such as build_alerts() and metric_card() — made the code easier to read and update.

11. Conclusion

CyberShield demonstrates that basic Python skills are enough to build a useful, visually professional security monitoring tool. The dashboard correctly identifies suspicious login patterns, presents the data clearly through charts and tables, and gives analysts the filters they need to investigate further. With a few additions — such as reading from a real log file or adding a time-window check — the same codebase could serve as a foundation for a genuine small-scale monitoring solution.
